## 3. 充电桩模块需求

### 3.1 用户场景（按优先级）

1. **找空位**：在教学楼或宿舍附近，哪个充电站现在有空桩？
2. **判断能不能马上充**：空闲数、快充/慢充功率、价格。
3. **看具体桩的状态**：A-03 是空闲还是故障？
4. **到点直达**：能一键打开官方页面/扫码页。

### 3.2 数据模型（写进 `apps/web/src/types.ts`）

```ts
export type ChargerStatus = 'idle' | 'charging' | 'fault' | 'offline' | 'unknown'

export type ChargerStation = {
  id: string
  name: string            // 「开元校区·图书馆东侧充电棚」
  campus: string          // 开元 / 西苑 / 景华 / 其他
  location?: string       // 楼区/方位描述
  total: number           // 总桩数
  idle: number            // 空闲桩数
  charging?: number       // 充电中
  fault?: number          // 故障
  fastPowerKw?: number    // 快充功率
  slowPowerKw?: number    // 慢充功率
  pricePerKwh?: number    // 元/度
  serviceFee?: number     // 服务费（若有）
  updatedAt: string
  sourceUrl?: string      // 官方页面/扫码跳转
}

export type Charger = {
  id: string
  stationId: string
  code: string            // 桩编号，如 A-03
  status: ChargerStatus
  powerKw?: number
  pricePerKwh?: number
  connector?: string      // 国标/快充口等
}

export type ChargerData = {
  fetchedAt: string
  stations: ChargerStation[]
  chargers?: Charger[]    // 只有拿到单桩明细时才填
  stale?: boolean
  error?: string
}
```

**约定**：`total / idle` 必填；单桩明细可选（数据源拿不到就不做展开，UI 自动降级）。

### 3.3 数据源与适配器契约

> 数据入口你在另一个 DSH 会话里已探明，本文**不写死 URL**。新建 `apps/desktop/src/lib/adapters/chargers.js`，导出：

```js
/**
 * @param {Engine} engine  共享浏览器窗口（已登录态）
 * @param {{campus?: string}} [opts]
 * @returns {Promise<ChargerData>}
 */
async function fetchChargers(engine, opts) { ... }

module.exports = { fetchChargers }
```

实现要求：

1. **优先走接口**：若页面是 SPA 且调 JSON 接口，仿照 `card.js` 的做法——`engine.load(页面)` 后，在页面上下文里用同步 `XMLHttpRequest` 调接口（同源、自动带 Cookie）；若接口需要令牌，从 `localStorage.token` 取并加 `Authorization: Bearer <token>`（`classroom.js` 里就是这个套路）。
2. **兜底走 DOM**：接口不可用时，等待页面渲染后读 DOM。等待条件必须基于**真实数据元素**，不要用"表格数量 > N"这种易被骨架骗过的条件。
3. **不要在适配器里做登录**：登录由 `session.ensure()` 统一处理；适配器只负责取数。
4. **失败语义**：拿不到数据时 **throw**（让 IPC 层回落缓存），不要返回空数组冒充成功。

### 3.4 IPC / 桥接契约

`apps/desktop/src/main.js`：

```js
ipcMain.handle('haust:refreshChargers', async (_e, opts) => {
  const t0 = Date.now()
  try {
    const data = await withEngine(() => chargers.fetchChargers(engine, opts))
    if (data && data.stations && data.stations.length) {
      store.write('chargers', data)
      log(`chargers ok ${Date.now() - t0}ms n=${data.stations.length}`)
      return data
    }
    const cached = store.read('chargers')
    if (cached && cached.stations && cached.stations.length) return { ...cached, stale: true }
    return data
  } catch (err) {
    log(`chargers FAIL ${err.code || ''} ${err.message}`)
    const cached = store.read('chargers')
    if (cached && cached.stations && cached.stations.length) return { ...cached, stale: true }
    throw err
  }
})
```

同步改三处：
- `haust:cached` 返回值里加 `chargers: store.read('chargers')`
- `preload.js` 加 `refreshChargers: (opts) => ipcRenderer.invoke('haust:refreshChargers', opts)`
- `env.d.ts` 加对应签名与 `cached.chargers`

**硬性要求**：必须走 `withEngine(...)`。所有取数共用同一个浏览器窗口，并发会互相打断导航——这是本项目踩过的坑（表现为"点了刷新没反应"）。

### 3.5 UI 规格

顶部工具条（参考 `rooms.css` 的 chip 样式）：

- 校区筛选 chips：`全部 / 开元 / 西苑 / 景华`（按数据里实际出现的 campus 动态生成）
- 开关：「只看有空位」
- 搜索框：按站点名 / 楼区关键字过滤
- 右侧：「刷新」按钮（只刷本模块）+「重读」

列表（站点卡片，一行一卡）：

```
[空闲 3/12]  开元校区·图书馆东侧充电棚
             位置：图书馆东侧 · 快充 60kW · 慢充 7kW · 1.2 元/度
             更新于 21:32 · [在浏览器打开]
```

- 空闲数用颜色区分：`idle>0` 绿色徽标、`idle==0` 灰色、`fault>0` 橙色提示
- 点击卡片展开单桩网格（编号方块，颜色：空闲绿 / 充电中蓝 / 故障红 / 未知灰）；没有单桩数据时**不显示展开箭头**
- 排序：有空的优先 → 空闲数降序 → 站点名
- 空态：「暂无充电桩数据，点刷新」
- 错误：顶部橙色横幅显示 `error`，同时保留旧数据（`stale`）
- 加载：骨架卡片 ×3，不要空白

同时把本模块纳入全局「全部刷新」流程（`App.tsx` 的 `refresh()`，加一步 `await step('充电桩', ...)`）。

### 3.6 刷新与缓存

| 项 | 策略 |
|---|---|
| 缓存文件 | `userData/data/chargers.json`（沿用 `store.js`，**目录必须是 `data/`，不能用 `cache/`**——会和 Chromium 自带缓存目录打架，文件会被清掉，本项目踩过） |
| 手动刷新 | 立即取数 |
| 进入页面 | 60 秒内不重复请求；超过则静默刷新 |
| 失败 | 回落缓存 + `stale: true`，界面标注"数据可能不是最新" |
| 空结果 | **绝不覆盖缓存** |

### 3.7 隐私

- 不新增任何账号密码存储；复用现有 DPAPI 凭据与 `persist:haust` 登录态
- 不上报任何数据；只访问学校官方域名
- 若数据源需要扫码/支付，**只提供跳转**，不在 App 内完成

## 4. 技术约束与已知坑（务必遵守）

1. **串行队列**：所有 `engine` 操作必须包在 `withEngine(() => ...)` 里，否则并发抢窗口。
2. **隐藏窗口不渲染**：有些站点的 SPA 在隐藏/后台窗口里完全不执行（表现为 `htmlLen≈700`、`localStorage` 空、页面白屏）。解法：`win.setOpacity(0); win.setSkipTaskbar(true); win.show()` 后再取数，`finally` 里 `engine.hide(); win.setOpacity(1)`。
3. **登录态判定**：最终 URL 命中 `loginExt / cas.haust.edu.cn / vpn.haust.edu.cn / auth.htm / passport` 即为失效，抛 `code: 'NO_SESSION'`。
4. **空结果不覆盖缓存**；解析成功但为 0 条时，回落缓存并打日志。
5. **等待 + 重试**：页面等待 45s，失败后再等 6s 重试一次，仍失败才报错。
6. **日志**：每次取数写一行到 `userData/data/app.log`（`log()` 已实现，`VERIFY=1` 时同时写 `build/verify/m0.log`）。
7. **electron 二进制**：pnpm 可能装出两份 electron，其中一份缺 `dist/`。`scripts/electron-path.cjs` 已做自动探测，勿改坏。
8. **验证模式**：`pnpm --filter @haust/desktop verify` 会走 `HAUST_VERIFY=1`，产出 `build/verify/*.json|png`；调试单个模块可用 `HAUST_ONLY=xxx` 环境变量（现有 exam/room 分支可参照，改完记得删掉 room 相关）。
9. **构建产物路径**：打包后 web 资源在 `process.resourcesPath/web`，开发时在 `apps/web/dist`，`main.js` 已按 `app.isPackaged` 分流。

## 5. 验收标准（逐条可测）

1. 侧边栏第 5 项显示「充电桩」，点击进入不再出现任何「空教室」字样。
2. 全量刷新后，充电桩列表至少显示 1 个站点，且 `空闲/总数` 与官方页面一致（抽样 3 个站点人工比对）。
3. 站点卡片展示：名称、校区/位置、空闲/总数、功率、价格、更新时间。
4. 「只看有空位」开关生效；搜索框按关键字过滤生效；校区 chips 过滤生效。
5. 有单桩数据时点击卡片能展开单桩网格，状态颜色正确；无单桩数据时无展开入口。
6. 断网或接口 500 时：顶部橙色错误横幅 + 保留上次数据（`stale`），界面不空白、不崩。
7. 清空缓存后重启 App，充电桩页显示空态而不是报错。
8. 时间戳验证：手动刷新后「更新时间」必须变化；连续点两次，第二次应命中 60 秒节流（日志无重复请求）。
9. `apps/web/src` 全局搜索 `classroom`、`空教室`、`空闲教室` 均为 0 命中（`docs/` 与构建产物除外）。
10. `pnpm --filter @haust/web build` 与 `pnpm --filter @haust/desktop dist` 均成功，产出 `release/河科大校园助手-0.1.0-安装版.exe`。

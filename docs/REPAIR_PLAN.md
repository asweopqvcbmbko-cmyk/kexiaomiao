# 依赖顺序与退出条件
1. **先验证账户隔离。** 固定当前源码快照及 0.1.7 APK 摘要，用授权测试账号核对 P0-1。先记录 A 的可识别测试课程，再清凭据并切 B，覆盖缓存、离线启动及旧请求晚返回。产出脱敏证据并判定是否发生越界。此项可用现有 APK 开始。
2. 记录可重复构建命令、依赖、签名证书摘要与变体。顺序为 pnpm build:web → mobile 下 npm run sync → mobile/android 下 gradlew.bat assembleDebug。在隔离副本中完成；修复模板测试的目标包名。通过构建和启动基线后再发布修复版本。
3. 根据第 1 项结果修复身份缓存和在途请求；核对凭据迁移、Cookie 清理与混合内容。以双账号冷/热启动和授权登录回归作为退出条件。
4. 账户边界稳定后修复空表、校园卡重读、轮询错误状态及开发模式初始化。逐项添加可判定的离线回归，再做校园数据对账。
5. 对账充电桩、通知、任务，检查系统栏及动效。空调单列为未接入需求。两端解析差异优先通过共享测试发现，保留现有技术栈。

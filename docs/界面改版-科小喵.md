## 三、任务勾选动画（按附件原样实现）

1. 点击后立刻给行加 `.marking-complete`：勾选框 `checkPop` 弹动、标题 `task-title::after`
   以 `taskStrike` 从 0→1 绘制（0.48s，`transform-origin:left`），整行 `pointer-events:none` 防重复点击。
2. **750ms 后**才写入完成状态、把任务移进「已完成」并更新统计（原型同款时序）。
3. 恢复未完成：立刻从已完成记录移除、插回待办，删除线消失。
4. `prefers-reduced-motion: reduce` 时跳过动画直接完成。

# 附：安卓 APK（数据层已接通）

## 现状

APK 能编译、安装，界面是新的，**数据层也接上了**：充电桩已是真实数据（实测 17/436 · 21 个点位）；
教务与学习通各自有登录入口，登录后课表/考试/通知/校园卡/作业随堂都走同一套解析代码。

没有账号我无法替你完成登录，所以「登录之后的那几步」需要你扫码/输密码后自己确认。

## 架构

桌面版靠 Electron 的一个隐藏 BrowserWindow 抓页面；安卓没有 BrowserWindow，就用
**一个自写的 Capacitor 插件**顶上：

```
apps/web/src/android/            ← 数据层（浏览器版）
├── engine.ts                    SchoolBrowser 插件的 load / run / waitFor（对齐桌面 lib/engine.js）
├── http.ts                      CapacitorHttp：Cookie 头、重定向、GBK 解码、重试（对齐 lib/chaoxing/http.js）
├── auth.ts                      学习通 Cookie（CookieManager 就是饼干罐，不再存文件）
├── api.ts                       实现 window.haust 的 20 个方法
├── store.ts 逻辑内联在 api.ts    localStorage 当缓存（key 与桌面版同名）
└── lib/                         从桌面端逐行移植的纯逻辑（require→import，逻辑未改）
    ├── eams.ts notices.ts card.ts      教务 / 通知 / 校园卡适配器
    ├── parse.ts activities.ts chaoxing.ts   学习通
    └── chargers.ts zzsx.ts areas.ts    充电桩

mobile/android/app/src/main/java/cn/edu/haust/campusassistant/
├── SchoolBrowserPlugin.java    open / close / load / eval / cookies / clearCookies / openExternal
└── MainActivity.java           注册插件
```

两个关键实现细节（都是踩过的坑）：

1. **隐藏 WebView 必须串行**。教务、通知、校园卡共用一个 WebView，桌面版靠 `withEngine()` 排队；
   安卓侧在 `api.ts` 里加了同样的串行锁 `withEngine()`，否则并发调用会互相把页面顶掉。
2. **登录判定不能只看 URL**。学校 CAS 会连跳几页，中间页也挂在 jwgl 域名下，
   早期版本因此把「未登录」误判成「已登录」。现在插件会等 URL 连续两次不变（`settle`）再返回，
   `status()` 还会读页面正文里有没有「课表查询/退出」这类登录后特征。

## 安卓端踩到的坑（校外访问那条路）

学校早已把教务/一网通办挂到深信服 aTrust（`vpn.haust.edu.cn`）后面，校外打开
`jwgl-haust-edu-cn-s.haust.edu.cn` 会 302 到 `controller/v1/public/verify`，再由
注入的 `sf-webproxy/web_proxy.js` 接管。由此产生三个和桌面版不一样的现象，都已收口：

1. **登录要过两道 CAS**。`CAS(cas.haust.edu.cn)` 登录后落在教务「统一身份认证登录」
   落地页，点「登录」还会再跳 `CAS(cas-haust-edu-cn-s)` 要再登一次。
   早期版本只做第一道 → 用户以为登录好了，其实没进教务（「已经登陆了但没同步」的根因）。
   现在：落地页自动点「登录」，两道 CAS 表单都用保存的账号自动填。
2. **EAMS 页面拿不到它自己的 JS 框架**。经 webvpn 中转后，`homeExt.action` /
   `courseTableForStd.action` 返回的 HTML 里没有 jQuery/bg.js（`typeof jQuery === 'undefined'`），
   于是页面里的 `searchTable()` 永远不跑，课表/考试表不会在浏览器端渲染出来。
   → 改成直接取服务端渲染好的表格入口（只读 GET）：
   `courseTableForStd!courseTable.action?ignoreHead=1&setting.kind=std&semester.id=…&ids=…`、
   `stdExamTable!examTable.action?ignoreHead=1&semester.id=…`，解析逻辑一行没改。
3. **隐藏 WebView 只有一个**，`status()` 以前不排队，会和 `refreshCourses` 互相顶掉页面
   （表现为 `登录已失效`）。现在 `status/login` 也进串行锁，并且同一个数据源单飞（`single()`），
   `App.refreshAll` 重叠调用直接复用同一个 Promise。

另外两条经验：

- **Cookie 必须手动落盘**：WebView 的 Cookie 默认异步刷盘，进程被杀就丢。
  现在登录窗开着时每 3 秒 `CookieManager.flush()`，`close()`/每次 `load` 结束时也刷，
  并在 `MainActivity.onPause/onStop` 再刷一次。
- **超星风控**：连续整轮扫描（39 门课 + 详情）会被拦成「安全验证」页（`len=4527`、
  只有 `ucode/ccc` 两个 input），而且**不能拿这个结果覆盖缓存**。现在 5 分钟内复用上次结果、
  失败一次就退避 10 分钟、并发从 3/4 降到 2/3、随堂轮询从 3 分钟放宽到 20 分钟。

## 第三轮：交互手感与安卓壳的适配（本轮）

| 登录后「有概率刷不出数据」 | ① App 的 `refreshAll` 改成「跑完再补一遍」的队列（以前登录后的刷新会被登录前那次吞掉）；② `refreshCourses/Exams/Card` 遇 `NO_SESSION` 会清会话缓存、自动重登并重试一次（`recoverSession`）；③ 校园卡等待从 ~43s 收紧到 ~13s，且排到通知之后，不再堵住课表；④ 教务连点会撞「请不要过快点击」反刷页，两次 load 之间加 700ms 间隔并识别反刷页重试一次；⑤ 空状态改成「没登录 / 没拉到 / 真没有」三种说法，不再用「今天没有排课」冒充 |

# 充电桩模块（智惠充电）· 实现说明

> 本文描述**已经实现**的东西，不是需求稿。上一版 `docs/需求-充电桩模块.md` 里的数据源部分（含云享充电）已作废。
> 落盘时间：2026-11-04。原始采集脚本（Python，参考实现）在另一个工作区：`<同机>/charge-watch/`。

---

## 1. 一句话

侧边栏「充电桩」页展示河南科技大学校园内**智惠充电**各楼栋的实时空闲枪位：按区域筛选、按空闲降序、标出距离，数据来自公开接口，**不需要登录学校系统、不需要任何账号、不依赖 Python**。

## 2. 数据源（唯一）

```
POST https://app.zzsx.cn/wxConfig/nearEqui
Content-Type: application/json;charset=UTF-8
Referer: https://app.zzsx.cn/wx/

{ "longitude": 112.4208, "latitude": 34.59693,
  "srcId": 27, "distance": 3000, "page": 1, "limit": 50 }

→ { "code": 200, "count": 46, "data": [
      { "code": "SGR00000312", "totalLines": 10, "free": 0, "charging": 10,
        "distance": 13.0, "lat": "34.596811", "lng": "112.4208",
        "address": "河科大开元校区菁园12" } ] }
```

- 零鉴权：无 token / 无 Cookie / 无微信环境要求。
- `srcId=27` 是「智惠充电」的供应商号，写死在 H5 打包代码里。**失效时**按 `charge-watch/README.md`「srcId 失效了怎么办」重取，只改 `apps/desktop/src/lib/chargers/rules.json` 的 `srcId` 即可，不用动代码。
- 证书主机名对不上，Python 参考实现用的是 `CERT_NONE`，Node 侧对应 `rejectUnauthorized: false`（`http.js` 默认如此）。
- **云享充电已下线**：它的 Cookie 来自「PC 微信登录态 + openid」，无法随 App 分发，且只覆盖公教楼；按需求决定不接。要重新接回来看第 10 节。

## 3. 采集管线

| 步骤 | 逻辑 | 代码 |
|---|---|---|
| 分页 | `limit=50`，最多 10 页；`chunk.length < limit` 或 `rows.length >= count` 时停 | `zzsx.js#fetchRaw` |
| 半径阶梯 | 3000 → 5000 → 10000 米，首个非空结果胜出 | `zzsx.js#fetchWithLadder` |
| 清洗 | `address` 按 `-` 切分：前半点位名，后半明细 | `zzsx.js#normalize` |
| 聚类 | 同名 + 80m 内**单链**聚类（haversine），距离取簇内最小 | `zzsx.js#mergeDevices` |
| 命名 | `labels`（设备号→名，智惠用不上）→ `name_rules` 正则 → 原名 | `areas.js#displayName` |
| 区域 | 扫 `area_aliases`，首个「别名出现在原始名里」的胜出，都不中归「其他」 | `areas.js#canonicalArea` |
| 二次聚合 | 同一楼栋会被平台拆成多个点位（嘉园4号楼 ×4、菁园1号楼 ×4），按「区域 + 展示名」合并成一张卡 | `index.js#aggregate` |

实测基线（2026-11-04 22:41）：**46 台设备 / 436 路 / 21 个合并点位 / 聚合后 13 个楼栋**。

## 4. 代码结构

```
apps/desktop/src/lib/chargers/
├── http.js      # POST JSON，15s 超时 + 3 次指数退避 + rejectUnauthorized:false
├── zzsx.js      # 分页 / 清洗 / 聚类（逐行对齐 check_ports.py）
├── areas.js     # 区域归属 + 展示名
├── rules.json   # 锚点、srcId、半径、合并距离、命名规则、区域别名
└── index.js     # collect()：串起上面几步并聚合，纯 Node，不 require electron
```

调用链：
```
renderer  window.haust.refreshChargers()
   → main.js  ipcMain.handle('haust:refreshChargers')   # 不走 withEngine
   → chargers.collect()
   → store.write('chargers', data)                      # userData/data/chargers.json
```

**为什么不走 `withEngine`**：`withEngine` 是给那个唯一浏览器窗口用的串行队列；充电桩只发 HTTP，插进去只会让慢刷新堵住课表。

## 5. 契约

`ChargerData`（`apps/web/src/types.ts`）：

```ts
{
  fetchedAt: string
  anchor: { name, lat, lng }
  radius: number            // 实际用了哪一档
  rawDevices: number        // 接口原始设备条数
  rows: ChargerRow[]        // 一行 = 一个楼栋（已聚合）
  byArea: Record<string, { points, devices, total, free }>
  totals: { points, devices, total, free }
  coverageNote: string
  stale?: boolean
  error?: string
}
```

`ChargerRow`：`area / display / raw / devices / deviceCount / points / total / free / charging / distance / error`。

失败语义（刻意从严）：

| 情况 | 行为 |
|---|---|
| 接口 `code !== 200` | 抛错，带响应片段 |
| 网络/证书/超时 | 3 次退避后抛错 |
| **解析出 0 条** | **抛错**（`智惠充电没有返回任何点位`），不写缓存、不当成功 |
| 有缓存时失败 | 回落缓存 + `stale: true`，界面显示「可能是旧数据」 |
| 连续点刷新 | `chargerPromise` 去重，不并发打两遍接口 |

## 6. UI

- 工具条：区域 chips（`全部` + 数据里出现的区域）｜搜索（楼栋/区域/设备号）｜`只看有空位`（默认开）｜`刷新`
- 摘要：全局 `空闲/总枪位`、点位数、设备数、更新时间；筛选时另起一行 `当前筛选：N 个楼栋 · 空 a/b`
- 卡片：左侧大号 `空闲/总数`，中间楼栋名 + 区域 + 点位数/设备数 + 距锚点米数 + 充电中，右侧百分比与设备号
- 配色：`free>=3` 或 `空闲率>=50%` 绿色；`1~2` 橙色；`0` 灰色（`0` 的卡默认被筛掉）
- 徽标：名称含「大功率」→ `快充`；`total>=40 且 free<=1` → `大站几乎满`
- 页脚固定说明：**智惠只覆盖生活区，教学楼无桩位数据**
- 充电桩**不依赖学校登录**：`refresh()` 里这一步排在登录判定之前，教务会话挂了照样能刷

## 7. 已知坑

1. **同栋多点位**：不聚合就会连续出现 4 张「嘉园4号楼」。聚合在 `index.js`，别在 UI 里再做。
2. **`address` 不可靠**：会重名、个别能标到几公里外；不要用它算位置，用 `lat/lng` + `distance`。
3. **接口偶发超时**：退避重试要保留，别把超时当「没有桩」。
4. **H5 在微信外会被 `isWechat()` 重定向**：只调接口，不要试图用浏览器打开 `app.zzsx.cn/wx/`。
5. **`srcId` 是写死的**：失效时接口会返回 `code != 200` 或 0 条，报错文案已指向 `rules.json`。
6. **缓存目录必须是 `data/`**：叫 `cache` 会被 Chromium 当自己的缓存目录清掉。

## 8. 怎么验证

```powershell
# 1) 只跑采集（不开窗口、不要登录），产出 build/verify/chargers.json + m0.log
$env:HAUST_ONLY='charger'; corepack pnpm --filter @haust/desktop verify

# 2) 顺带截一张「充电桩」页（前端人工核对）
$env:HAUST_ONLY='charger'; $env:HAUST_SHOT='1'; corepack pnpm --filter @haust/desktop verify
#   → build/verify/tab-charger.png

# 3) 与 Python 参考实现对拍（开发期用，App 运行不需要 Python）
$env:HAUST_PY='C:\...\Python313\python.exe'
$env:CHARGE_WATCH_DIR='<同机>\charge-watch'
node apps/desktop/scripts/parity-chargers.cjs
#   断言：点位集合一致、总路数一致、距离一致、空闲漂移 <= 15
#   退出码 0 通过 / 1 不一致 / 2 环境缺失跳过
```

`HAUST_ONLY=charger` 分支故意**不调** `ensureSession`，所以它 3 秒内就能跑完，不会弹登录窗。

## 9. 覆盖边界

智惠只在生活区布桩：菁园、嘉园、乾园、德园、小北门、致远楼、文科楼（实测）。**公教楼 / 教学楼区域没有任何桩位数据**——原来唯一覆盖公教楼的是云享充电，已按需求下线。界面页脚常驻说明，避免误判成「教学楼没桩」。

## 10. 以后要接回云享充电

`charge-watch/HANDOFF.md` 里有完整方案（Cookie 来源、`ChargeCarRange`/`ChargeCar` 接口、`err_input` 判定、7 天有效期）。接入时的三条硬要求：

1. `err_input` 必须显式判定：会话过期时接口返回 **HTTP 200 + `[{"par":"err_input"}]`**，不判就会得到「1 台设备 / 0 路」的幽灵数据。
2. `cdz.gpsserver.cn` 证书主机名不匹配 → 必须 `rejectUnauthorized: false`。
3. 设备状态是 `glztN !== '1'` 才算空闲；`secrets.json` 要放在 `userData` 根目录（不要放 `data/`，会被「清空缓存」删掉）。

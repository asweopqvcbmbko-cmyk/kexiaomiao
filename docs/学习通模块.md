## 2. 登录模型（踩过三次坑，别改回去）

1. 独立持久分区 `persist:chaoxing`，扫码登录窗口挂在这里；
2. 登录成功那一刻把 Cookie **按域名分组**存一份到 `<userData>/chaoxing_session.enc`（DPAPI 加密）。

- **坑 A：强杀丢登录态。** Chromium 只在正常退出时才可靠落盘 Cookie。所以登录成功要 `cookies.flushStore()` **并**自己写一份。
- **坑 B：各子域 Cookie 不能拼成一条串。** `passport2.chaoxing.com` 的 `JSESSIONID` 与 mooc/i.chaoxing 是两套会话，混着发会让服务端认错会话 → 请求被 302 回登录页，看起来像"登录失效"。现在存 `[{name,value,domain}]`，每请求按目标 host 过滤。
- **坑 C：验证模式没有主窗口。** 登录窗一关会触发 `window-all-closed` 把采集进程带走；`ERROR` 里现在 `VERIFY` 时不退。

## 3. 作业接口

| 用途 | 请求 |
|---|---|
| 学校 fid / 账号名 | `GET https://i.chaoxing.com/base` |
| 课程列表 | `GET https://mooc2-ans.chaoxing.com/mooc2-ans/visit/courselistdata?courseType=1&courseFid=<fid>&courseTeacherid=0&courseOrderBy=0` |
| 课程中间页 | `GET https://mooc1.chaoxing.com/visit/stucoursemiddle?courseid=&clazzid=&cpi=&ismooc2=1&v=2`（取隐藏域 `workEnc/openc/enc`） |
| 作业列表 | `GET https://mooc1.chaoxing.com/mooc2/work/list?courseId=&classId=&cpi=&ut=s&openc=&enc=<workEnc>&t=&stuenc=&isdisplaytable=2` |
| 截止时间 | 作业列表条目 `data` 里的详情页 URL，解析 `作答时间: MM-DD HH:MM 至 MM-DD HH:MM` |

`workEnc` 是动态签名，页面回「没有此页面访问权限」时重取课程页再试。截止时间**只在详情页**，所以只对未完成的逐份请求（并发 4、上限 80、总预算 90s）。详情页时间没有年份，`nearestDateTime()` 取离今天最近的年份补全。

## 4. 随堂检测（课堂活动）

### 4.1 接口（2026-11-05 上课时段用真实账号实测）

**能拿到"进行中"的只有逐课程接口**：

```
GET https://mobilelearn.chaoxing.com/v2/apis/active/student/activelist
    ?fid=0&courseId=<课程>&classId=<班级>&_=<毫秒>
→ { data: { activeList: [ { id, activeType, status, startTime, endTime,
                             nameOne, nameTwo, nameFour, url, logo, … } ] } }
```

实测结论（**这些是跑出来的，不是文档抄的**）：

| 结论 | 证据 |
|---|---|
| `mobilelearn` **不挑 UA** | 浏览器 UA / 明文官方 UA / 不带 UA，三次都 200 且内容一致 |
| ⚠️ `ppt/activeAPI/courseactivelist`（"全部课程"那个）**不可靠** | 上课时段确实有 32 个进行中的活动，它的 `status=1` 却返回 **0 条**；`status=''` 只给最近 9 条且全是已结束的。**不要再用它做轮询** |
| v2 接口**不带 courseId 会 500** | 必须逐课程；39 门并发 4 约 3~4 秒（串行 10.2s） |
| **`endTime` 在进行中的活动里是有值的** | 例：高数「定义考查」`endTime` → 次日 07:45，`nameFour` 为 `剩余:20小时`。已结束的活动才是空字符串 |
| 随堂练习的 `activeType = 42` | 高数/线代里标题像「随堂练习」「定义考查」「2.6」的都是 42 |

`status`：1=进行中、2=已结束。类型码实测：2 签到、4 判断、5 问答、11 选人、14 问卷、17 直播、35 分组、**42 随堂**、43 投票、45 通知、48 资料、57 测验、77 练习。
**签到(2) 和通知(45) 不算"要做的事"，从列表里排除。**

### 4.2 筛选规则（`rules.json` 可调，改配置不用改代码）

```json
{ "allowedActiveTypes": [42, 77],      // 只留 随堂 / 练习；资料48、测验57、问答5、投票43、分组35、签到2、通知45 全不要
  "retainMonths": 2,                    // 参考时间早于「今天往前 2 个日历月」的丢弃
  "useTimetableWhitelist": true,        // 用本学期教务课表(14门)做白名单，过滤去年课程
  "ignoreCourses": ["大学化学A"] }      // 名字命中即永不显示
```

- **参考时间 = 截止时间优先，没有就用开始时间**；未来截止不设上限；随堂类两样都没有则丢弃（作业没有参考时间仍保留，比如"待互评"）。
- **课程**：先用白名单把要扫的课程从 39 门缩到本学期（39→~20，省一半请求），再对结果做二次校验；课表拿不到时**自动退化**为只按 `ignoreCourses` 过滤，不会把整页清空。
- **完成态**：⚠️ **学习通活动接口不返回学生完成态**——实测「已提交」的 3 条与「未做」的 2 条在 `userStatus` / `isLook` / `ifcommit` / `ismark` 上**完全相同**，活动详情接口（`getPPTActiveInfo`）也没有 per-user 字段。因此只能**本地手动标记**：每行有「✓ 完成」，点后写入 `data/done.json`，刷新和轮询都会过滤掉。
  - 本地标记必须**每一层都过一遍**，否则点过的又冒出来：网络采集走 `filterActivities({doneKeys})`；而 `data/tasks.json` 缓存是在标记**之前**写下的，所以启动读缓存、刷新失败降级读缓存这两条路径都要再过滤一次（主进程 `dropDone()`）。点「✓ 完成」时顺便把缓存快照也清一遍，避免下次启动先闪一下再消失。
- 页脚会显示「课堂活动已按本学期课表（14 门）过滤；已隐藏：非随堂/练习 N」，让"为什么少了"是可见的。

## 5. 未完成判定（作业）

```js
DONE_MARKS           = ['已完成','已提交','待批阅','已批阅','已批改','已互评']
REVIEW_PENDING_MARKS = ['待互评','未互评','待评价']   // 优先级更高
```

`待互评` 算未完成并高亮；`已互评` 算完成；「已提交待互评」这种复合状态不能被「已提交」吞掉。实测：39 门课 → 未完成 3 条（2 未交 + 1 待互评），已完成 117 条。

## 6. 代码结构与 IPC

```
apps/desktop/src/lib/chaoxing/
├── http.js        # Node https：跟重定向、gbk/utf8 解码、超时重试、可指定/省略 UA
├── auth.js        # 分区登录 + Cookie jar（DPAPI）+ 按 host 取 Cookie
├── parse.js       # 作业侧纯解析（课程/作业列表/作业详情/未完成判定/年份补全）
├── activities.js  # 课堂活动：列表接口、判定、转任务行、去重、筛选
├── rules.json     # 随堂检测判定配置（改这里不用改代码）
└── index.js       # collect()=作业+活动；collectPractices()=只查活动（轮询用）
```

IPC：`haust:refreshTasks`（全量）/ `haust:pollActivities`（只查活动）/ `haust:chaoxingStatus|Login|Logout`；缓存键 `tasks`（含 `activities`）。

**轮询**：主进程 `startActivityPoll()`，窗口存在时每 3 分钟调一次 `collectPractices({runningOnly:true})`（一次请求、不碰作业），有进行中时 `webContents.send('haust:activities')`。失败只在错误信息变化时记一行日志，不打扰上课。启动 20 秒后先探一次。

## 7. 界面

**随堂检测和作业是同一个列表**（要求：有的老师只发随堂、不发作业，不能把它当第二类处理）：

- 分组统一成：`进行中 / 已逾期 / 今天截止 / 3 天内 / 更晚 / 未标截止时间`；
- 「进行中」组里是正在进行的随堂检测（琥珀高亮 + 「已开始 X 分钟」）；已结束但在 48h 内的归入「未标截止时间」；
- 每行左侧只用徽标区分 `作业` / `随堂`，其余布局、排版、交互完全一致；
- 随堂行显示 `23:31 发起（已开始 12 分钟）`，作业行显示 `截止 … · 还剩 …`／`已逾期 …`；
- 没有 url 的随堂把「打开」置灰（这类活动只能在 App 里做）；
- 顶部横幅仍只在**有进行中随堂**时出现；
- 导航徽标 = 未完成作业 + 随堂检测，和页面上的「未完成 N 项」一致。

## 8. 边界

| 场景 | 行为 |
|---|---|
| 活动接口异常 | 只影响随堂分组，作业照常；`activitiesError` 里带原因 |
| 未登录 | `NO_LOGIN` 是状态不是故障：返回 `{loggedIn:false}`，界面显示去登录，并清掉本地 Cookie |
| 拿不到结束时间 | 显示开始时间，不算倒计时 |
| 未知名 activeType | 白名单外不显示（除非标题命中关键词） |
| 轮询失败 | 静默，保留上次结果 |
| 只读 | 全模块只有 GET；无任何签到/作答/提交请求 |

## 10. 已知限制

- 随堂检测是**课上临时**的东西：App 必须开着才能靠轮询提醒；关掉就只在下次打开/刷新时看到近 48 小时内的。
- `mooc1-api.chaoxing.com/gas/taskmsg`（App 原生"一次拿全部作业"的 JSON）裸请求 403，不可用。
- 39 门课里包含历史学期课程；`已互评/已批改` 已排除，但历史课里若真有「未交」也会列出来。要按本学期课表过滤可以再加。
